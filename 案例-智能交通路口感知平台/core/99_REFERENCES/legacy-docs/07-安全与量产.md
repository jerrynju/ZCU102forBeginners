# 07 - 安全设计与量产方案

## 1. 安全启动链

```
上电
 │
 ▼
BootROM（芯片内置，只读）
 ├── 验证 FSBL（RSA-4096 签名 + SHA3-384）
 ├── 密钥来源：eFUSE 中的 RSA 公钥哈希
 └── 失败 → 锁死（不回退到非安全启动）
 │
 ▼
FSBL（First Stage Bootloader）
 ├── 初始化 DDR、MIO
 ├── 加载 PMU Firmware
 ├── 加载 PL 比特流（AES-256 GCM 加密，密钥在 eFUSE）
 └── 加载并验证 U-Boot
 │
 ▼
U-Boot SPL
 ├── 验证 U-Boot 主体（RSA 签名）
 └── 加载并验证 Linux FIT Image
 │
 ▼
Linux 内核
 ├── IMA（完整性度量架构）验证关键文件
 ├── dm-verity 保护根文件系统只读区
 └── 启动应用程序（systemd）
```

### 1.1 eFUSE 烧写（量产时一次性操作）

```bash
# 使用 Vitis 的 program_flash 命令或 xsdb 烧写 eFUSE
# 警告：eFUSE 一旦烧写不可撤销！量产前在测试设备上充分验证

# 生成 RSA-4096 密钥对（生产环境必须使用 HSM 硬件安全模块保存私钥）
openssl genrsa -out production_key.pem 4096
openssl rsa -in production_key.pem -pubout -out production_pub.pem

# 生成 eFUSE 编程文件
bootgen -arch zynqmp -generate_hashes -efusefile efuse_config.xml

# efuse_config.xml 内容
# <efuse_config>
#   <rsapubkey_digest>1</rsapubkey_digest>   <!-- 烧写 RSA 公钥哈希 -->
#   <jtag_disable>1</jtag_disable>           <!-- 禁用 JTAG（量产必须）-->
#   <encrypt_only>1</encrypt_only>           <!-- 强制加密启动 -->
#   <black_iv>0</black_iv>                   <!-- 加密比特流的初始向量 -->
# </efuse_config>
```

### 1.2 加密比特流生成

```bash
# bootgen 配置文件（.bif）
# 生成带 AES 加密的 BOOT.BIN

the_ROM_image:
{
    [fsbl_config] opt_key
    [keysrc_enc] bbram_red_key  /* 密钥存储在 BBRAM（可清除）或 eFUSE（不可清除）*/
    [auth = rsa, encryption = aes, aeskeyfile = device_aes.nky]
    {
        [bootloader, destination_cpu = a53-0] fsbl.elf
        [destination_cpu = pmu]               pmufw.elf
        [destination_device = pl]             traffic_edge.bit  /* 比特流加密 */
        [destination_cpu = a53-0, exception_level = el-3]  bl31.elf
        [destination_cpu = a53-0, exception_level = el-2]  u-boot.elf
    }
}
```

## 2. OTA 远程升级

```
升级包结构：
  traffic_edge_v2.3.1.swu（SWUpdate 格式）
  ├── sw-description         # 升级描述文件（签名验证）
  ├── BOOT.BIN               # FSBL + FPGA 比特流 + U-Boot
  ├── image.ub               # Linux 内核 + 设备树
  ├── rootfs.ext4.gz         # 根文件系统（压缩）
  └── app.tar.gz             # 仅应用层（无需重启内核）
```

### 2.1 A/B 分区方案

```
eMMC 分区表（32GB）：
┌─────────────────────────────────────────────────────┐
│ Boot0 (4MB)   │ BOOT_A.BIN  │ 当前激活的启动分区 A   │
│ Boot1 (4MB)   │ BOOT_B.BIN  │ 备用启动分区 B          │
│ p1 (512MB)    │ /boot_a     │ kernel + dtb (分区 A)   │
│ p2 (512MB)    │ /boot_b     │ kernel + dtb (分区 B)   │
│ p3 (8GB)      │ /rootfs_a   │ 根文件系统 (分区 A)     │
│ p4 (8GB)      │ /rootfs_b   │ 根文件系统 (分区 B)     │
│ p5 (4GB)      │ /data       │ 持久数据（配置/日志）   │
│ p6 (剩余)     │ /tmp_ota    │ OTA 包下载临时区        │
└─────────────────────────────────────────────────────┘

U-Boot 环境变量记录当前激活分区：
  boot_slot=a          # 当前从 A 分区启动
  boot_count=0         # 启动成功计数（3次失败自动回滚）
```

### 2.2 SWUpdate 配置

```lua
-- sw-description（Lua 语法，SWUpdate 专用）
software =
{
    version = "2.3.1";
    hardware-compatibility = ["1.0", "1.1"];
    images:
    ({
        filename = "BOOT.BIN";
        type = "rawfile";
        device = "/dev/mmcblk0boot1";  -- 写入非活跃 Boot 分区
        sha256 = "abc123...";
    },
    {
        filename = "image.ub";
        type = "rawfile";
        device = "/dev/mmcblk0p2";    -- 写入非活跃 kernel 分区
        sha256 = "def456...";
    },
    {
        filename = "rootfs.ext4.gz";
        type = "raw";
        device = "/dev/mmcblk0p4";    -- 写入非活跃 rootfs 分区
        compressed = "zlib";
        sha256 = "789ghi...";
    });
    scripts:
    ({
        filename = "post_install.sh";
        type = "shellscript";
        -- 升级成功后切换 U-Boot 环境变量
    });
}
```

```bash
# post_install.sh — 升级完成后切换分区
#!/bin/sh
current=$(fw_printenv boot_slot | cut -d= -f2)
if [ "$current" = "a" ]; then
    fw_setenv boot_slot b
    fw_setenv boot_device_kernel /dev/mmcblk0p2
    fw_setenv boot_device_rootfs /dev/mmcblk0p4
else
    fw_setenv boot_slot a
    fw_setenv boot_device_kernel /dev/mmcblk0p1
    fw_setenv boot_device_rootfs /dev/mmcblk0p3
fi
fw_setenv boot_count 0  # 重置计数，允许 3 次失败后自动回滚
echo "Switched to slot: $(fw_printenv boot_slot)"
```

## 3. 量产测试方案

### 3.1 测试流程

```
工厂测试流程（FCT - Functional Circuit Test）：

1. 上电检测（< 5s）
   ├── 电源 Rails 电压检测（VCCINT/VCCAUX/3.3V/1.8V）
   └── 看门狗激活确认

2. JTAG 边界扫描（< 30s）
   ├── MPSoC 所有 MIO 引脚连通性
   ├── DDR4 数据总线验证
   └── FPGA IO 测试

3. 固件烧录（< 3min）
   ├── 通过 JTAG + xsdb 烧录 BOOT.BIN 到 eMMC Boot0
   ├── 通过 USB/SD 卡刷写 image.ub + rootfs
   └── 烧录设备唯一证书（device_id 绑定序列号）

4. 功能测试（< 5min）
   ├── Linux 启动，SSH 登录验证
   ├── DPU 推理测试（标准测试图片，检测结果对比 golden 文件）
   ├── 摄像头接口测试（MIPI 时序检测，帧计数）
   ├── 10GbE 回环测试（64B / 1500B / 9000B 帧）
   ├── CAN 总线自环测试
   ├── GPU PPS 信号检测
   └── 温度传感器读取（xsysmon）

5. 老化测试（8h，可并行多台）
   ├── 满负荷推理（4路摄像头输入模拟）
   ├── 温度监控（每分钟记录，TJ < 95°C）
   └── 错误计数（DDR ECC / AXI 总线错误）

6. 最终验收
   ├── 贴序列号标签
   ├── 防伪码写入（绑定设备证书）
   └── 装箱出库
```

### 3.2 自动化测试脚本

```python
# scripts/factory_test.py
import paramiko, time, json, sys

class FactoryTest:
    def __init__(self, device_ip: str, device_id: str):
        self.ssh = paramiko.SSHClient()
        self.ssh.set_missing_host_key_policy(paramiko.AutoAddPolicy())
        self.ssh.connect(device_ip, username='root',
                         key_filename='factory_key.pem')
        self.device_id = device_id
        self.results = {}

    def test_dpu_inference(self) -> bool:
        # 发送标准测试图片，检验推理结果
        self.ssh.exec_command("mkdir -p /tmp/test")
        sftp = self.ssh.open_sftp()
        sftp.put('golden/test_image.jpg', '/tmp/test/input.jpg')

        stdin, stdout, stderr = self.ssh.exec_command(
            "traffic_infer_cli /tmp/test/input.jpg /tmp/test/output.json"
        )
        stdout.channel.recv_exit_status()

        sftp.get('/tmp/test/output.json', '/tmp/output.json')
        with open('/tmp/output.json') as f:
            result = json.load(f)

        # 验证：测试图片应检测到 3 辆车，1 个行人
        cars    = sum(1 for o in result['objects'] if o['class'] == 'car')
        persons = sum(1 for o in result['objects'] if o['class'] == 'person')
        passed  = (cars == 3 and persons == 1)
        self.results['dpu_inference'] = {'pass': passed, 'cars': cars}
        return passed

    def test_10gbe(self) -> bool:
        # 本机回环测试
        cmd = "iperf3 -c 127.0.0.1 -p 5201 -t 10 -J"
        _, out, _ = self.ssh.exec_command(cmd)
        data = json.loads(out.read())
        bps = data['end']['sum_received']['bits_per_second']
        passed = bps > 9e9  # > 9 Gbps 视为通过
        self.results['ethernet'] = {'pass': passed, 'bps': bps}
        return passed

    def run_all(self) -> dict:
        tests = [
            ('dpu_inference',   self.test_dpu_inference),
            ('ethernet_10gbe',  self.test_10gbe),
        ]
        all_pass = True
        for name, fn in tests:
            try:
                result = fn()
                print(f"  [{('PASS' if result else 'FAIL')}] {name}")
                all_pass = all_pass and result
            except Exception as e:
                print(f"  [ERROR] {name}: {e}")
                self.results[name] = {'pass': False, 'error': str(e)}
                all_pass = False

        self.results['summary'] = {
            'device_id': self.device_id,
            'all_pass':  all_pass,
            'timestamp': time.strftime('%Y%m%d_%H%M%S')
        }
        # 上传测试报告到 MES 系统
        upload_to_mes(self.device_id, self.results)
        return self.results

if __name__ == '__main__':
    device_ip = sys.argv[1]
    device_id = sys.argv[2]
    tester = FactoryTest(device_ip, device_id)
    results = tester.run_all()
    sys.exit(0 if results['summary']['all_pass'] else 1)
```

## 4. 知识产权保护

```
防护层次：

层次 1 - FPGA 比特流加密
  → AES-256 GCM 加密比特流（密钥存在 eFUSE/BBRAM）
  → 即使读出比特流也无法逆向 PL 逻辑
  → 对应保护：ISP 算法、DPU 自定义扩展

层次 2 - 软件授权绑定
  → 读取 MPSoC 唯一 ID（IDCODE）生成授权码
  → 应用程序启动时验证授权码
  → 授权文件由云端服务器签发（私钥 RSA-2048）

层次 3 - AI 模型保护
  → xmodel 文件经过 Vitis AI 编译，非标准格式
  → 存储时 AES-256 加密，运行时解密到 DDR（利用 TrustZone 隔离）

层次 4 - 安全 Debug
  → eFUSE 禁用 JTAG 接口（量产后不可调试）
  → 应用日志不包含模型参数、密钥信息
```
