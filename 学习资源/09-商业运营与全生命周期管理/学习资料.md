## 二、OTA远程升级

### 1. OTA分类

| 类型 | 全称 | 说明 |
|-----|-----|-----|
| FOTA | Firmware Over-the-Air | 底层固件更新 |
| SOTA | Software Over-the-Air | 应用层更新 |
| AOTA | AI-Model Over-the-Air | AI模型更新 |
| COTA | Configuration Over-the-Air | 配置更新 |
| DOTA | Data/Diagnostic Over-the-Air | 数据/诊断更新 |
| XOTA | Everything Over-the-Air | 万物更新 |

### 2. 安全OTA架构
- TLS传输 + 签名验证 + A/B分区回滚
- 升级管理平台（可使用Mender/SWUpdate）
- 灰度发布与回滚策略

### 3. Bootloader设计要点
- **双Bank（Dual-Bank）结构**：Flash分为A、B两份轮用
- **完整性校验**：CRC32/SHA-256
- **真实性验证**：ECDSA/RSA数字签名（必须在Bootloader阶段完成）
- **回滚机制**：启动失败自动切回旧版本

### 4. OTA流程
1. **版本检测**：设备上报SN、HWID、FW_VER，云返回升级策略
2. **下载任务**：支持断点续传；低功耗设备常用HTTP Range或MQTT分片
3. **完整性校验**：SHA-256或CRC32；再做RSA/ECC公钥验签
4. **镜像写入**：AB双分区或外置Flash；关键字段写尾部，防止掉电
5. **重启切换**：Bootloader读ActiveSlot标志，进入新系统
6. **回滚检测**：系统自检失败写RollbackFlag，下一次启动回旧镜像

## 五、商业模式设计

### 1. 常见模式

| 模式 | 说明 |
|-----|-----|
| 硬件销售 | 一次性收入，利润来自BOM成本差 |
| 硬件 + 软件授权 | 分离硬件与算法IP，提升整体价值 |
| SaaS/云服务 | 边缘设备 + 云端分析，持续订阅收入 |
| 解决方案集成 | 交钥匙方案，附加集成服务费 |
