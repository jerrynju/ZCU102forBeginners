💻 ZCU102 开发板概览

Xilinx Zynq UltraScale+ MPSoC 评估平台的核心信息

💻
处理器系统 (PS)
ARM Cortex-A53 quad-core @ 1.5GHz

四核 ARM Cortex-A53 应用处理器，运行 PetaLinux 或自定义 Linux，负责高层控制、通信和深度学习推理调度。

⚙
可编程逻辑 (PL)
Xilinx ZU9EG FFVC1156 FPGA

包含 253K 个 Logic Cells、600 个 DSP slices 和 76Mb BRAM，适合实现高性能并行算法加速。

📊
内存子系统
4GB DDR4 + 512MB PS DDR

双通道 DDR4 SODIMM 接口（最高 2666 Mbps），PL 侧可通过 AXI 高速访问外部内存。

🔗
互联接口
AXI4 / AXI4-Stream / AXI-Lite

PS 与 PL 通过 AXI 互联（ACP、HP ports）通信，支持高带宽 DMA 数据传输和寄存器控制。

⚙ HDL Coder 入门学习路径

从基础概念到 ZCU102 上运行的完整流程，共 5 个步骤

1

📚 了解 HDL Coder 基础

HDL Coder 可以从 MATLAB 函数或 Simulink 模型自动生成可综合的 Verilog、SystemVerilog 和 VHDL 代码。生成的代码可用于 FPGA 编程、ASIC 原型和生产设计。

✅HDL Coder 支持定点转换优化、关键路径高亮显示、资源利用率预估，以及 DO-254 等安全标准要求的可追溯性。
MATLAB/Simulink Verilog/VHDL 代码生成
2

🎮 准备兼容的 Simulink 模型

创建一个 HDL 兼容的 Simulink 模型是代码生成的第一步。需要检查模型是否满足 HDL 代码生成的约束条件：

  • 使用 HDL Coder 支持的模块（如 DSP System Toolbox、Communications Toolbox）
  • 设置合适的采样时间、数据类型和维度
  • 使用 HDL Workflow Advisor 进行兼容性检查
  • 对于流式数据处理，使用简化流协议 (Simplified Streaming Protocol)
💬提示：使用 makehdltargetconfig 函数可以创建 HDL 目标配置对象来管理代码生成设置。
3

🔄 选择目标平台与 IP 核生成策略

针对 ZCU102 这类 SoC 平台，有三种主要的部署策略：

策略说明适用场景
IP Core Generation生成独立的 HDL IP 核，集成到 Vivado 工程中需要与其他 IP 组合的复杂系统
Reference Design基于预定义的参考设计模板一键部署快速原型验证、标准接口（AXI4-Stream/DDR）
Custom Board使用 hdlcoder.Board 定义自定义板卡特性非标硬件、量产产品

ZCU102 在 HDL Coder 中内置了三种参考设计模板：

  1. vivado_base — 基础设计，提供最小化的 PL-PS 连接框架
  2. vivado_stream — 流式接口设计，通过 AXI4-Stream 实现 PS↔PL 高速数据传输
  3. vivado_ddr4 — DDR4 内存访问设计，允许 FPGA 通过 AXI 直接读写外部 DDR 内存
4

🚀 综合与比特流生成

使用 HDL Workflow Advisor 执行以下流程：

目标设置

选择 Target workflow 为 "IP Core Generation"，Target platform 选择 "Xilinx Zynq ZCU102 Evaluation Kit"，Reference Design 选择合适模板（base/stream/ddr4）。

代码生成

HDL Coder 将 Simulink 子系统转换为 Verilog/VHDL 代码，同时生成 AXI 接口包装器（AXI-Lite 寄存器映射 + AXI4-Stream 数据通路）。支持速度/面积优化、流水线插入、RAM 映射等高级选项。

Vivado 综合 & 实现

HDL Workflow Advisor 自动调用 Vivado 进行综合 (Synthesis)、布局布线 (Implementation)，最终生成 Bitstream (.bit 文件)。整个过程可在 MATLAB 内完成，无需手动操作 Vivado GUI。

编程 FPGA

通过 JTAG 或以太网将 Bitstream 下载到 ZCU102 的 PL 部分。如果使用参考设计，还会生成配套的嵌入式 Linux 驱动程序。

5

📊 验证与调试：JTAG AXI Master

部署完成后，可以使用 socAXIManager 或 HDL Verifier 的 JTAG-based AXI Manager 直接从 MATLAB 访问 FPGA 内部状态：

  • 读写 DDR 内存中的数据缓冲区
  • 读写 BRAM（Block RAM）内容
  • 通过 AXI-Lite 配置/读取 IP 核寄存器
  • 在仿真和真实硬件之间无缝切换
% 创建 AXI Manager 对象连接到 ZCU102
axiManagerObj = socAXIManager('Xilinx');
% 写入 DDR 内存地址
writememory(axiManagerObj, 0xA0000000, int16(data));
% 读取 BRAM 内容
data = readmemory(axiManagerObj, 0x40000000, 1024);
✅JTAG AXI Master 不需要嵌入式软件或网络连接，仅通过 JTAG 线缆即可直接访问 FPGA 所有 AXI 从设备——非常适合早期硬件调试！

💻 SoC Blockset 学习路径

掌握异构计算平台的硬件/软件协同设计与部署

1

💻 理解 SoC 架构建模

SoC Blockset 让你在 Simulink 中对 SoC 硬件架构进行建模，包括：

  • ARM 处理器核 — Cortex-A53 (应用)、Cortex-R5 (实时)
  • FPGA 可编程逻辑 — 自定义硬件加速器
  • 内存子系统 — DDR、BRAM、Cache 层级
  • 外设接口 — GPIO、UART、Ethernet、AXI 总线

核心价值在于：可以在同一个 Simulink 模型中表示整个系统的硬件架构和软件行为，从而分析不同硬件/软件分区的性能影响。

2

📦 创建 SoC 模型与任务分区

使用 SoC Project Template 创建新项目后，你需要决定哪些算法运行在 ARM 处理器上（软件），哪些运行在 FPGA 上（硬件）：

运行位置特点适合的任务
ARM 处理器 (PS)灵活、易修改；顺序执行；低延迟简单任务控制逻辑、通信协议、预处理、深度学习推理调度
FPGA 逻辑 (PL)高度并行、确定性时序；低吞吐延迟信号处理、图像卷积、矩阵运算、数据格式转换
3

⚙ IP 核生成与 SoC Builder

确定硬件分区后，使用 SoC Builder App 自动化部署流程：

生成 HDL IP 核

调用 HDL Coder 将标记为 Hardware 的子系统转换为 HDL 代码和 IP 核包装。

集成到参考设计

SoC Builder 自动将 IP 核集成到选定的参考设计中，配置 AXI 互连、时钟域和中断路由。

生成嵌入式软件

Embedded Coder 为 ARM 处理器部分生成 C/C++ 代码，包括 Linux 用户空间应用或裸机程序。

构建与下载

自动调用交叉编译工具链构建软件，生成 SD 卡启动镜像，并通过 JTAG/以太网编程板卡。

4

🎨 深度学习 + 图像预处理联合部署

SoC Blockset 提供了一个专门的 "Deep Learning with Preprocessing Interface" 参考设计，用于将深度学习推理和自定义预处理逻辑一起部署到 ZCU102：

⚠此参考设计的 FPGA 用户逻辑必须包含两个简化的 AXI Manager 协议接口：一个用于与 DL IP 核交互，另一个用于 FPGA 逻辑与 DDR 之间传输数据。

该架构的数据流为：

  1. 输入视频数据通过 AXI4-Stream 进入 FPGA
  2. FPGA 中的预处理逻辑（resize、归一化、色彩空间转换等）处理像素数据
  3. 处理后的数据写入 DDR 内存
  4. DLP (Deep Learning Processor) 从 DDR 读取数据进行推理
  5. 推理结果通过 AXI-Lite 返回给 MATLAB/ARM 进行后续处理

🧠 Deep Learning FPGA 学习路径

将神经网络模型部署到 ZCU102 实现边缘 AI 推理加速

1

📖 硬件准备：SD 卡引导设置

在使用 Deep Learning HDL Toolbox 部署到 ZCU102 之前，必须先完成硬件初始化：

安装支持包

安装 Deep Learning HDL Toolbox Support Package for AMD FPGA and SoC Devices，其中包含 ZCU102 的预置配置文件和固件镜像。

选择硬件

在 Add-Ons 面板中选择你的板卡类型（ZCU102 或其他支持的 AMD/Xilinx 板卡）。

配置主机网卡

设置主机的网络接口参数，确保能通过以太网与 ZCU102 通信。可能需要管理员权限（因为要配置网卡参数）。

写入固件到 SD 卡

向导会引导你将 MathWorks 提供的固件镜像写入 SD 卡。此固件是一个精简的 Linux 系统，包含必要的驱动和网络服务。

设置跳线帽与连接

ZCU102 跳线设置：将板卡配置为从 SD 卡启动模式。具体跳线位置参见板卡原理图。

验证连接

上电后通过以太网 ping 通板卡，确认 MATLAB 能成功建立连接。

2

🧠 准备深度学习网络

Deep Learning HDL Toolbox 支持将序列深度学习网络 (Series Network) 部署到 FPGA。典型的准备工作：

  • 在 MATLAB 中使用 Deep Learning Toolbox 训练或导入预训练的网络
  • 支持的网络层类型：卷积层、全连接层、ReLU、Batch Normalization、Max/Average Pooling、Softmax 等
  • 量化支持：将浮点权重转换为整数表示以减少资源占用
  • 输入尺寸需固定（不支持动态尺寸）
% 示例：加载预训练网络
net = resnet18();  % 或 load('my_trained_network.mat');
% 分析网络结构
analyzeNetwork(net);
3

🚀 使用 dlhdl.Workflow 编译与部署

dlhdl.Workflow 是深度学习 FPGA 部署的核心对象，提供端到端的工作流管理：

% 步骤 1: 创建 Workflow 对象
hW = dlhdl.Workflow('Network', net, ...
              'Target', dlhdl.Target('Xilinx', 'ZCU102'));
% 步骤 2: 编译网络 (生成 HLS C++ 代码)
hW.compile();
% 步骤 3: 部署到 FPGA (编程 Bitstream)
hW.deploy();
% 步骤 4: 执行预测
result = hW.predict(inputImageClass);
% 步骤 5: 查看资源利用率
buildInfo = hW.getBuildInfo();

各方法的作用：

方法作用输出
compile()将网络的每一层转换为 HLS C++ 代码C++ 源码 + 资源估算报告
deploy()调用 Vivado HLS 综合、Vivado 实现，生成 Bitstream.bit 文件 + 编程到 FPGA
predict()将输入数据发送到 FPGA，执行推理，返回结果分类结果 / 性能指标
getBuildInfo()获取编译/部署后的详细统计信息LUT/DSP/BRAM/FF 使用量、频率、延迟
4

📊 性能分析与优化

部署完成后，你可以进行详细的性能分析：

  • 资源利用率：查看 LUT、DSP、BRAM、Flip-Flop 的使用量和百分比
  • 时钟频率：确认 FPGA 实际运行频率是否满足时序要求
  • 推理延迟：单帧图像从输入到输出的总耗时
  • 吞吐量：每秒处理的帧数 (FPS)

💪 什么是 HDL Coder？

HDL Coder 是 MATLAB 的代码生成工具箱，可以从以下来源生成可综合的硬件描述语言代码：

  • MATLAB 函数 — 直接从 .m 文件生成 HDL
  • Simulink 模型 — 从模型中的子系统生成 HDL
  • Stateflow 图表 — 从状态机生成 HDL

输出格式支持 Verilog、SystemVerilog 和 VHDL 三种主流 HDL 语言。

🎯 核心能力

  1. HDL IP Core Generation — 生成可复用的 IP 核，集成到 Vivado/Quartus 工程
  2. FPGA/SoC 部署 — 通过参考设计一键生成 Bitstream 并编程板卡
  3. 实时硬件部署 — RCP (快速控制原型) 和 HIL (硬件在环) 仿真
  4. 优化与分析 — 速度/面积优化、关键路径分析、资源估算
  5. 可追溯性 — Simulink 模块 ↔ HDL 代码行级别的追溯映射

📋 主要功能类别

类别描述
HDL Code Generation from MATLAB从 MATLAB 函数生成 HDL 代码
HDL Code Generation from Simulink从 Simulink 模型/子系统生成 HDL
High-Level Synthesis (HLS)从 MATLAB 高层次合成生成 HDL
HDL IP Core Generation面向 IP 核集成的代码生成工作流
Supported HardwareAMD/Xilinx、Intel/Altera、Microchip/Microsemi
Real-Time DeploymentRCP/HIL 仿真与 Speedgoat FPGA I/O

hdlcoder.Board 类 — 自定义板卡注册

hdlcoder.Board Class Reference | 属性 · 方法 · 用法示例

💻 类概述

hdlcoder.Board 是一个板卡注册对象，用于描述 SoC 平台的自定义板卡特性。当你需要在 HDL Coder 中使用非官方支持的开发板时，通过此类定义板卡的硬件参数。

📝 创建方式

% 创建空的板卡对象
board = hdlcoder.Board();
% 设置属性
board.BoardName = 'MyCustomZCUBoard';
board.FPGAVendor = 'Xilinx';
board.FPGAFamily = 'Zynq UltraScale+';
board.FPGADevice = 'xczu9eg-ffvb1156-2-e';
board.FPGAPackage = 'ffvb1156';
board.FPGASpeed = '2';
board.SupportedTool = 'Vivado Tool 2023.1';

📊 核心属性一览

属性名类型说明
BoardNamechar vector板卡名称标识符
FPGAVendorchar vectorFPGA 厂商 ('Xilinx', 'Intel', 'Microchip')
FPGAFamilychar vectorFPGA 系列 (如 'Zynq UltraScale+')
FPGADevicechar vector具体器件型号 (如 'xczu9eg-ffvb1156-2-e')
FPGAPackagechar vector封装类型
FPGASpeedchar vector速度等级
SupportedToolchar vector支持的 EDA 工具及版本
JTAGChainPositionchar vectorJTAG 链中的位置

🎭 关联方法

创建 Board 对象后，通常配合以下函数使用：

  • addexternaliointerface(board) — 添加外部 I/O 接口（LED、按钮、DIP 开关等）
  • adddevicetree(board) — 设备树配置（用于 Linux 驱动识别）
  • setupCustomReferenceDesign(board) — 设置自定义参考设计
💬对于 ZCU102 这种已被官方支持的板卡，无需手动创建 Board 对象 —— 直接在 HDL Workflow Advisor 中选择即可。Board 类主要用于完全定制的硬件平台。

hdlcoder.ReferenceDesign 类 — 自定义参考设计注册

hdlcoder.ReferenceDesign Class Reference | 属性 · 方法 · 参考设计注册流程
▼

🎾 类概述

hdlcoder.ReferenceDesign 是一个参考设计注册对象，用于描述 SoC 平台的自定义参考设计。通过此类，你可以注册一个自定义的参考设计，让 HDL Coder 在 IP 核生成时将其作为目标参考设计使用。

📝 创建方式

% 创建参考设计对象
refdesign = hdlcoder.ReferenceDesign('SynthesisTool', 'Vivado');
% 设置核心属性
refdesign.ReferenceDesignName = 'My Custom Reference Design';
refdesign.BoardName = 'MyCustomZCUBoard';
refdesign.SupportedToolVersion = '2023.1';
refdesign.CustomConstraints = {'my_constraints.xdc'};
refdesign.CustomFiles = {'my_files.tcl'};
refdesign.DeviceTreeName = 'devicetree.dtb';
refdesign.AddMATLABAXIManagerParameter = true;
refdesign.MATLABAXIManagerDefaultValue = 'on';
refdesign.IPCacheZipFile = 'ip_cache.zip';
refdesign.ReportTimingFailure = true;
refdesign.HasProcessingSystem = true;
refdesign.GenerateIPCoreDeviceTreeNodes = true;

📊 核心属性一览

属性名说明
ReferenceDesignName参考设计名称（在 Workflow Advisor 中显示）
BoardName关联的板卡名称
SupportedToolVersion支持的 Vivado/Quartus 版本
CustomConstraints自定义约束文件（XDC/UCF）
CustomFiles自定义 Tcl 文件（用于 Vivado 项目定制）
DeviceTreeName设备树文件名（用于 Linux 驱动）
AddMATLABAXIManagerParameter是否添加 AXI Manager 参数到参考设计
MATLABAXIManagerDefaultValueAXI Manager 参数的默认值
IPCacheZipFileIP 缓存 Zip 文件路径
ReportTimingFailure是否报告时序失败
HasProcessingSystem参考设计是否包含处理系统 (PS)
GenerateIPCoreDeviceTreeNodes是否生成 IP 核设备树节点
ResourcesUsed参考设计使用的资源信息

🎭 主要方法

  • Public Methods — ReferenceDesign 对象本身没有特殊方法，主要通过属性配置
  • 关联函数 — hdlcoder.createreferencedesign() 可创建参考设计模板文件
✅ZCU102 的三种内置参考设计（vivado_base / vivado_stream / vivado_ddr4）都是 hdlcoder.ReferenceDesign 的实例。你可以参考它们的实现来创建自己的参考设计。

🔍 如何选择目标平台？

完成 Simulink 建模或 MATLAB 函数编写后，选择目标平台时需要考虑以下因素：

  1. 设备类型 — FPGA only? SoC? 还是 ASIC?
  2. 厂商 — Xilinx (AMD)? Intel? Microchip?
  3. 具体板卡 — 评估板还是自定义板？
  4. 部署方式 — IP 核集成？参考设计？还是全定制？
  5. 是否需要软件 — SoC 场景需要考虑 ARM 处理器上的软件部分

📊 硬件-软件协同设计工作流

针对 SoC 平台（如 ZCU102）的完整部署流程分为两大部分：

Part A: FPGA 部分（硬件）

A1. 准备部署模型

标记要生成 HDL 的子系统，设置目标设备、时钟频率、复位同步等参数。

A2. 生成 IP 核和 Bitstream

HDL Coder 生成 HDL 代码 + AXI 包装器，调用 Vivado 综合实现，最终得到 .bit 文件。

A3. 运行和验证

在目标硬件上编程 Bitstream，通过 JTAG AXI Manager 或嵌入式软件验证功能正确性。

Part B: 处理器部分（软件）

B1. 配置软件接口到 FPGA

定义 ARM 处理器如何与 FPGA IP 核通信：共享内存地址、寄存器映射、中断号。

B2. 生成 C 代码

Embedded Coder 为 Simulink 中标记为 Software 的部分生成 C 代码。

B3. 硬件-软件部署

将 Bitstream + 交叉编译的可执行文件 + Linux 镜像打包，通过 SoC Builder 部署到板卡。

✅对于 ZCU102，推荐从 "IP Core Generation" + "AXI4-Stream Interface" 参考设计开始，这是最常用且文档最完善的工作流。

AXI4-Stream 接口 Zynq 工作流详解

Generate IP Core with AXI-Stream Interface | 流式数据处理 · 高速 PS-PL 通信
▼

💬 为什么需要 AXI4-Stream？

在 Zynq SoC 中，ARM 处理器(PS) 和 FPGA(PL) 之间需要高效地传输大量连续数据（如图像帧、音频样本、传感器数据流）。AXI4-Stream 协议专门为此设计：

  • 无地址开销 — 不像 AXI4-Memory Mapped 需要每次传输指定地址
  • 突发传输 — 一个 TVALID/TREADY 握手可传输整帧数据
  • 低延迟 — 点对点直连，无需经过总线交换矩阵
  • 背压机制 — TREADY 信号让下游可以控制上游速率

📏 完整工作流步骤

Step 1: 使用 Simplified Streaming Protocol 建模

在 Simulink 中添加输入/输出数据端口和控制信号端口，HDL Coder 会自动生成符合 AXI4-Stream 规范的接口逻辑。

所需工具箱：DSP System Toolbox、Embedded Coder、Embedded Coder Support Package for Xilinx Zynq Platform、HDL Coder Support Package for Xilinx FPGA and SoC Devices、Simulink Coder、Vision HDL Toolbox、SoC Blockset Support Package for AMD FPGA and SoC Devices

Step 2: 生成带 AXI4-Stream 接口的 HDL IP 核

在 HDL Workflow Advisor 中：选择 Target workflow = "IP Core Generation"、Target platform = "Xilinx Zynq"、Reference Design = "AXI4-Stream" (对应 vivado_stream 模板)、配置 IP 核的接口为 Streaming 类型、点击 Generate。

Step 3: 将 IP 集成到 AXI4-Stream 兼容的参考设计

生成的 IP 核会被自动集成到 Vivado 工程中。参考设计提供了：PS-PL AXI4-Stream 通路（DMA 或直接连接）、时钟域 crossing (CDC) 逻辑、复位同步电路、必要的 AXI Interconnect 配置。

Step 4: 使用 AXI4-Stream Driver Block 生成 ARM 可执行文件

在 Simulink 中添加 AXI4-Stream Driver Block（来自 Embedded Coder Support Package），它代表运行在 ARM 上的用户空间驱动程序。Embedded Coder 会生成对应的 C 代码，交叉编译后在 Zynq 的 ARM 核上运行。

✅这个工作流非常适合视频处理、通信基带处理等需要持续数据流的场景。ZCU102 上的 vivado_stream 参考设计就是为此优化的。

JTAG AXI Master 访问 FPGA 内存

Access FPGA Memory Using JTAG-Based AXI Manager | DDR/BRAM 读写 · 无需嵌入式软件
▼

🔧 什么是 JTAG AXI Manager？

JTAG-based AXI Manager 是一种特殊的调试机制，允许你仅通过 JTAG 线缆就能访问 FPGA 内部的任何 AXI 从设备（Slave）—— 包括 DDR 内存控制器和 BRAM 控制器。这意味着：

  • 不需要嵌入式软件 — 不依赖 Linux 驱动或裸机程序
  • 不需要网络连接 — 仅靠 JTAG USB 线即可工作
  • 早期调试利器 — 在软件还没准备好之前就可以验证硬件功能

📏 完整使用步骤

1. 集成 AXI Manager IP 到 Vivado 工程

在你的 Vivado 工程中添加 AXI Manager IP 核。这会在 FPGA 中插入一个小的 JTAG-to-AXI 桥接逻辑。需要重新综合和实现生成新的 Bitstream。

2. Vivado 仿真验证

首先在 Vivado Simulator 中验证设计：从 MATLAB 发起读写命令，确认仿真波形中 AXI 事务正确完成。

% MATLAB 仿真中读写
axiManagerObj = socAXIManager('Xilinx');
writememory(axiManagerObj, ddrAddr, writeData);
readData = readmemory(axiManagerObj, ddrAddr, numWords);

3. 编程 FPGA

将包含 AXI Manager IP 的 Bitstream 编程到 FPGA。此时 JTAG 链路打通，MATLAB 可以直接访问 FPGA。

4. 从 MATLAB 读写 FPGA 内存

与仿真相同的 API，但现在操作的是真实硬件：

% 读写 DDR 内存
writememory(axiManagerObj, 0xA0000000, int16(myData));
result = readmemory(axiManagerObj, 0xA0000000, length(myData));
% 读写 BRAM
writememory(axiManagerObj, bramAddr, uint8(configData));
config = readmemory(axiManagerObj, bramAddr, 256);
⚠JTAG AXI Manager 的读写带宽受限于 JTAG 时钟频率（通常几 MHz ~ 几十 MHz），不适合大数据量的高频传输。生产环境应优先使用 AXI-DMA 或以太网等高速接口。
